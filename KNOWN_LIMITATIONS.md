# Known limitations

Kept current as work proceeds. Anything that affects users also belongs in the release notes.

- **v0.3.0 features Unverified (2026-10-24).** Everything new in 0.3.0 — pins, undo mark-all-read, the consolidated row menu, power keys, exact-time tooltips, open-all-unread, folded repeats, per-type alert rules, Focus Assist suppression, the one gentle re-alert, the morning digest, per-account bubble colours, the fallback extraction strategies, session-state detection, renderer self-healing, the staleness line, backup/restore, portable mode and the ARM64 build — is built and unit-tested (265 Core tests) but has not run on a real Windows desktop yet. RELEASE_CHECKLIST.md's v0.3.0 section is the pass that promotes each item.
- **Focus Assist scope (v0.3.0).** FaceTray reads Windows' shell-wide notification state (the signal behind Focus Assist, presentation mode and fullscreen games) and holds pop-ups and sounds while it says not to disturb; counting continues. Windows does not expose per-app or per-rule Focus Assist details to applications, so the shell state is all FaceTray — or any app — can honour. If reading the state fails, pop-ups are allowed rather than suppressed on a guess.
- **Exact times are best-effort (v0.3.0).** A row's tooltip shows an exact time only when Facebook's page exposes a machine-readable time for that row (a `<time datetime>` or an `<abbr title>`); many rows carry nothing but the relative label, and their tooltips show just the label. Nothing is guessed.
- **Morning digest simplification (v0.3.0).** “N new since your last digest” counts notifications FaceTray has *seen arrive* since the last digest — it is not a Facebook-side query, so on the first morning it can only count what arrived while FaceTray was running.
- **Portable mode (v0.3.0).** With `portable.txt` next to the executable, all data lives in `FaceTray-data` beside it — moving that folder moves everything, sign-ins included. Deleting the marker (or running a copy without it) switches back to the AppData folders; the portable and AppData worlds coexist and never merge.
- **v0.2.0 features Unverified (2026-10-24).** Everything new in 0.2.0 — stacked avatars, search, type filters, deeper history, snooze, the custom pop-up, quiet hours, sound, the global hotkey, tray-menu recents, multi-account profiles, settings export/import, adaptive polling, auto-prune, the update notifier, the extraction-health banner, the diagnostics panel, ticker themes and text size — is built and unit-tested (197 Core tests) but has not run on a real Windows desktop yet. RELEASE_CHECKLIST.md's v0.2.0 section is the pass that promotes each item.
- **Windows runtime Verified for core flows (2026-10-23).** Across SEAN's v0.1.0 and v0.1.1 runs on his Windows machine: the app launches, sign-in works, the live notification list matches Facebook's own menu, avatars render, the Unread filter works, the tray counter bubble is correct, clicking a notification opens it in the default browser, the Settings window renders with the expected states, and the installer works. Secondary behaviours still exercised only in code/tests (each poll interval, autostart, toasts, the uninstaller's data choices) are tracked in RELEASE_CHECKLIST.md.
- **DOM extraction field-Verified for the standard notifications layout (2026-10-23).** The extraction script uses semantic signals only (notification links carrying `notif_id` / `notif_t`, aria-labels, roles, visible text) and never obfuscated class names; on SEAN's machine it listed his real notifications identical to Facebook's own menu (same items, order, grouping and type badges). Facebook can change its layout at any time; if row extraction ever misses, the counter still degrades to the page-title count. Since v0.3.0 the reader tries three semantic strategies in order (notification-link anchors, post/story permalinks with a time leaf, structured rows) and Settings → Diagnostics reports which one produced the list — the fallbacks themselves are Unverified until a real layout change exercises them.
- **Avatars: v0.1.1 fix Verified (2026-10-23).** In v0.1.0 every avatar rendered as the grey placeholder: Facebook often serves profile pictures as SVG `<image>` elements or `background-image` divs, which the v0.1.0 script ( `<img src>` only) did not capture. v0.1.1 captures all three forms and logs captured-but-failed avatar loads; SEAN's v0.1.1 capture shows real profile photos on every row.
- **Unread detection is heuristic.** The script looks for an explicit “Unread” accessible label in the row; rows Facebook does not label that way may appear read. The title count corrects the *number*, not individual rows.
- **Multi-avatar rows show up to three faces.** Facebook stacks several avatars for group actions; since v0.2.0 the ticker renders up to three overlapping avatars per row (up to four are parsed and cached).
- **Actor bolding is best-effort.** Names are bolded when a known action verb separates them from the rest of the text; otherwise the whole line renders regular rather than guessing.
- **Time labels come from Facebook.** Grouping (Today vs Earlier) and the time line use Facebook's relative labels (`9h`, `1d`); an unrecognized label lands in Earlier.
- **Clear data does not sign you out.** Settings → Clear data removes the *active* account's cache, local read marks, snoozes and pins. The WebView2 profile folder cannot be deleted safely while the app runs, so full sign-out means deleting the session folder shown in Settings after closing FaceTray (or choosing “also delete” in the uninstaller). Removing an account in Settings does delete that account's session and data, on Save.
- **Ticker themes.** The default palette is still Facebook dark. v0.2.0 adds a Light palette and a Follow Windows mode (Windows light/dark, and real system colours under high contrast); badges and the unread dot keep their colours in every theme. All themes are **Unverified** on a real desktop. Settings and Login use the family palette and standard controls.
- **Adaptive polling has no battery / metered awareness.** The cadence adapts to unread counts and quiet streaks only; it does not slow down on battery saver or metered connections.
- **The update check is the only non-Facebook network call.** Once per launch (Settings can turn it off) FaceTray asks GitHub's API for the latest release. Nothing is ever downloaded automatically.
- **Switching accounts restarts FaceTray.** A WebView2 environment is bound to its session folder per process, so a switch saves settings and relaunches (the MuseDesktop pattern). Only one account polls at a time.
- **Unsigned.** Plain EXE and installer ship unsigned per SEAN's standing rule; SmartScreen may warn on first run.
